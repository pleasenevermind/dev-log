# 2026-01

## 2026-01-06

- Set up a scratch harness for tool-calling evals: 12 public API specs, 40 prompts, JSON-schema validation on every call. Baseline first, no retries, so failures stay visible.

## 2026-01-07

- Baseline pass@1 is 0.62. Most misses are wrong argument types, not missing calls. Added a validator that reports the exact JSON pointer before scoring.

## 2026-01-09

- Wrote a failure taxonomy: wrong tool, missing arg, bad type, extra arg, refusal, timeout. Re-scored the same traces by hand; 9 of 25 failures were schema errors the validator missed.
- Found three schema gaps: nullable enums, integer vs number, and additionalProperties. Pinned a stricter validator and re-ran the set.

## 2026-01-16

- Added one retry on schema failure with the validation error appended to the prompt. pass@1 goes to 0.74, but p95 latency doubles.
- Retries fix type errors and nothing else. Wrong-tool failures come back identical, so the retry budget is wasted there. Keeping retries only for parse errors.

## 2026-01-19

- Compared three providers on the same 40 prompts. Tool-call formatting differs more than quality: one emits parallel calls by default, one needs explicit `tool_choice`, one silently truncates long schemas.
