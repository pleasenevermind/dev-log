# 2026-08

## 2026-08-04

- MCP month. Stood up a minimal server with two tools and one resource. The protocol is simple; the permission model is the part to get right.
- Tool descriptions are prompt text. A malicious server can hide instructions in a description and the client will happily include them in context.
- Wrote a test that injects an instruction into a tool description and checks whether the model follows it. It does, in 3 of 5 variants.

## 2026-08-05

- Client-side allowlist by server and tool name. Also pinned server versions; an unpinned npx invocation is a supply-chain hole with a friendly name.

## 2026-08-06

- Reviewed three popular MCP servers for filesystem access. Two default to the whole home directory. Changed the config to a scoped workspace.

## 2026-08-07

- Typosquatting: registered names are not verified. A package named close to a popular server is a realistic attack. Added a lockfile with hashes.
- Sigstore and cosign for release artifacts. Verification is straightforward; the hard part is getting projects to publish signatures at all.

## 2026-08-08

- SBOM generation with syft. The output is noisy but useful for spotting abandoned transitive dependencies. CycloneDX is easier to diff than SPDX.

## 2026-08-10

- Secret scanning on the agent workspace. gitleaks catches the obvious patterns; added a custom rule for the fake keys used in the injection tests.
- OAuth for remote MCP servers: device flow is the least bad option for a CLI. Scopes should be per-server, not one token for everything.
- Token storage: OS keychain, not a dotfile. Added a check that refuses to start if the token file is world-readable.

## 2026-08-11

- Dependency pinning across the harness. Lockfiles for Python and Node, hashes for downloads, and a weekly update job that runs the eval before merging.

## 2026-08-12

- Reviewed the MCP spec's auth section. Resource indicators and audience checks matter; a token minted for one server should not work on another.
- Wrote a small proxy that logs every MCP request and response. Useful for debugging and for spotting tools that return more data than they should.

## 2026-08-13

- Tool output is untrusted input. Added a size cap and a sanitizer before results go back into context. A 2MB response is a context bomb.
- Also strip ANSI escapes and HTML comments. Both are cheap places to hide instructions that survive naive text handling.

## 2026-08-14

- Threat model update: the server, the tool description, the output, and the install path are all attack surface. The client is the only place to enforce policy.

## 2026-08-17

- Wrote an MCP server checklist: scoped filesystem, no shell by default, allowlisted egress, signed releases, per-server tokens, request logging.
