# 2026-02

## 2026-02-02

- Started the retrieval track: 300 docs from public documentation, 60 questions with known answers. Chunked at 800 tokens with 100 overlap as the baseline.
- Baseline recall@5 is 0.71. Long chunks win on recall but waste context; 400-token chunks retrieve more precisely and lose the answer more often.

## 2026-02-03

- Added BM25 next to dense retrieval. Hybrid with reciprocal rank fusion gets recall@5 to 0.83, mostly on error codes and exact identifiers.
- Dense-only fails on version strings and CRLF-style literals. BM25 catches them. Fusion weights matter less than having both.

## 2026-02-04

- Tried three embedding models on the same chunks. The smallest is within 3 points of the largest on this set, so the cost argument wins for now.
- Normalization matters: one model expects L2-normalized vectors and silently returns cosine-incompatible scores otherwise. Added an assertion.
- Indexed everything into sqlite-vec for the harness. 300 docs is nothing, but the API is simple enough to keep the eval self-contained.

## 2026-02-05

- Added a reranker over the top 20. Recall@5 goes to 0.88, but p95 latency triples. Testing a smaller cross-encoder next.

## 2026-02-06

- The small reranker keeps most of the gain at a third of the latency. Keeping it. Also added a cutoff: if the top score is below a threshold, answer 'not found' instead of guessing.

## 2026-02-10

- Built a citation check: every claim must point to a retrieved chunk ID, and the ID must exist. Cheap to run, catches fabricated references.
- Found the model citing chunk 7 for facts from chunk 3 when they overlap. Tightened the prompt to quote the supporting sentence before the claim.
