# 2026-04

## 2026-04-02

- Switched tracks to Solidity. Set up Foundry and ported a small vault contract into a test harness. forge test runs in under a second, which makes fuzzing practical.
- First invariant: total assets equals the sum of balances plus fees owed. Wrote it as a handler-based invariant test instead of a unit test.

## 2026-04-06

- Fuzzing found a rounding bug in share math on the first run. Deposit 1 wei, withdraw, repeat: the attacker gains a wei per cycle.
- Fixed with virtual shares and an offset. Re-ran 10k runs; the invariant holds. Added a regression test with the exact seed.
- Gas snapshot: deposit 71k, withdraw 64k. forge snapshot in CI so a change that adds 5k gas is visible in the diff.

## 2026-04-07

- Reentrancy: wrote a malicious receiver that re-enters withdraw. The naive vault drains. The fixed version uses checks-effects-interactions order and a nonReentrant guard.

## 2026-04-08

- Ran Slither over the contracts. Mostly noise on the test harness, but it flagged an unchecked return value in the fee transfer.
- Added Echidna for property testing. It found a path where fees could exceed the configured cap after three deposits, which the Foundry fuzzer missed.

## 2026-04-14

- Access control: the vault owner can pause but not move funds. Wrote a test that asserts the owner cannot transfer, then tried to break it with a delegatecall.

## 2026-04-15

- Upgradeability: read the UUPS proxy pattern. Storage layout is the risk, not the code. Wrote a slot-layout check that fails if a variable moves.

## 2026-04-16

- Oracle manipulation: a spot price from a single pool is trivially flash-loanable. Switched the test harness to a TWAP and added a staleness check.

## 2026-04-20

- ERC-4337: read the EntryPoint flow. A paymaster can sponsor gas, which means the paymaster's validation rules are the security boundary, not the wallet.

## 2026-04-21

- Built a minimal UserOperation by hand and traced it through the EntryPoint. The signature covers the userOpHash, which includes the chain ID and EntryPoint address.
- Paymaster validation runs before execution and must not read mutable state that execution can change. That constraint is easy to violate and hard to debug.

## 2026-04-22

- Gas profiling for the 4337 path: validation is the expensive part, and a bad paymaster context can add 40k gas. Cached what can be cached without breaking the rules.
- Bundler simulation is not a substitute for validation. A userOp that simulates fine can still fail on-chain if the paymaster deposit changes between simulation and inclusion.

## 2026-04-23

- MEV: read about sandwich attacks on DEX swaps. Added a slippage check and a deadline to the test router. The deadline is the part most examples omit.

## 2026-04-24

- Wrote a small fork test against mainnet state. Pinning the block number is mandatory or the test drifts. Foundry's createSelectFork makes this easy.

## 2026-04-27

- Reviewed the vault for decimal assumptions. Mixing 6- and 18-decimal tokens breaks share math in the usual way. Normalized to 18 internally and tested both.
