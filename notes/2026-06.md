# 2026-06

## 2026-06-01

- Set up vLLM locally to compare a 7B model against the API baseline. Throughput is good; the setup is the annoying part.

## 2026-06-03

- Quantization: ran the same eval on fp16, AWQ 4-bit, and GGUF Q4. AWQ loses 2 points, GGUF loses 4 on this set.
- Perplexity tracks the eval gap loosely. The tasks that break are the ones with strict output formats, not the reasoning-heavy ones.
- Memory math: 7B at fp16 needs about 14GB for weights plus KV cache. At 4-bit the weights fit in 4GB, which changes which GPUs are usable.

## 2026-06-05

- KV cache size scales with context and batch. At 8k context and batch 8, the cache is larger than the quantized weights. Easy to forget when sizing a box.
- Paged attention keeps fragmentation down. vLLM's default settings are fine; the failure mode is raising the GPU memory fraction too high and OOMing during a long run.

## 2026-06-08

- Speculative decoding: a small draft model speeds up generation when the acceptance rate is high. On code-like output it is a clear win; on creative text it is close to neutral.

## 2026-06-11

- Prompt caching: identical prefixes are cheap on two providers, not on the third. Restructured the system prompt to put stable text first.

## 2026-06-12

- Structured output: grammar-constrained decoding removes JSON parse errors entirely. The cost is a small latency hit and less freedom in wording.

## 2026-06-17

- Batching: continuous batching keeps the GPU busy, but per-request latency gets worse under load. Measured the tradeoff at 1, 4, and 16 concurrent requests.
- At 16 concurrent, throughput is 6x and p95 is 4x. For an interactive agent, cap concurrency at 4 and queue the rest.

## 2026-06-18

- Context length: doubling the window doubles the KV cache and roughly doubles prefill time. Long prompts are not free even when the model supports them.

## 2026-06-23

- Tried a 1.5B model for routing and classification. It is good enough to pick a tool category and too weak for argument generation. Split the pipeline.

## 2026-06-24

- Draft-then-verify: small model writes the call, large model checks it. Cheaper than large-model-only and catches most malformed calls, but adds a round trip.

## 2026-06-26

- Benchmarked the local stack against the API on 40 tasks. Local is 3x cheaper at steady state and 2x slower for single requests. Break-even is around 10k requests/month.
- The operational cost is real: driver versions, CUDA mismatches, and model weights are now my problem. Wrote a setup script so the next rebuild is boring.

## 2026-06-29

- Quantized the KV cache to fp8. Memory drops by half with a small accuracy hit on long-context tasks. Kept it for the batch jobs, not the interactive path.
