# 2026-10

## 2026-10-01

- Started a supervisor/worker setup: one planner, three workers with disjoint tool sets, a shared task queue. The planner never calls tools directly.
- First run deadlocked: two workers waited on a dependency that the planner had already marked complete. Added explicit task states and a timeout.

## 2026-10-02

- Message bus: Redis streams with consumer groups. At-least-once delivery means every handler must be idempotent, same as the tool calls in January.
- Dead-letter queue after three failures. The failures are mostly schema errors, which the validator catches before the handler.

## 2026-10-03

- Shared memory is the hard part. Workers need context but should not see each other's raw transcripts. Gave each worker a scoped summary plus the task spec.

## 2026-10-05

- Handoff format: a JSON object with goal, constraints, artifacts, and open questions. The planner validates it before assigning; malformed handoffs are rejected early.

## 2026-10-13

- Evaluation: the multi-agent run is slower and more expensive than the single loop on 30 of 40 tasks. It wins on tasks that need two independent checks.
- The win is verification, not parallelism. Two workers checking different failure modes catch more than one worker retrying.

## 2026-10-16

- Planner prompt: enumerate subtasks, assign owners, define done. The model still writes vague done criteria. Added a schema that requires a testable condition.

## 2026-10-17

- Retries: a worker failure returns to the planner, not to the worker. The planner decides whether to retry, reassign, or drop. Fewer duplicate side effects.

## 2026-10-20

- Context budget across agents: each worker gets a slice, and the planner holds the summary. Without a budget, the planner's context grows until it truncates.
- Truncation is silent in two SDKs. Added a token count check before every call and a hard failure instead of a quiet trim.
- The failure mode is ugly: a truncated plan looks valid but drops constraints. A hard failure is better than a plausible wrong answer.

## 2026-10-28

- Added a critic agent that only sees the final artifact and the original goal. It catches missing constraints that the planner forgot.
- The critic is cheap and improves the pass rate, but it also flags style preferences as errors. Constrained it to the spec.

## 2026-10-29

- Cost: multi-agent runs cost 3.4x the single loop. The critic is 10% of that; the planner's repeated summaries are the rest.
- Cached the planner summary by task hash. Cost drops by a third without changing the pass rate.

## 2026-10-30

- Wrote the October summary: supervisor, bus, handoff schema, critic. The architecture is useful for verification-heavy tasks and overkill for simple ones.
